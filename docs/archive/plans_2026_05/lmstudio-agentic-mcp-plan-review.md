# LM Studio Agentic MCP Plan - 검토 및 개선 의견

작성된 `lmstudio-agentic-mcp-plan.md`와 현재 코드베이스, 워크플로우를 심층 분석한 결과, 별도의 서버를 만들지 않고 기존 `newauto-stepwise`를 Agentic Hub로 승격시켜 로컬 PC 제어(PowerShell, 파일 시스템)와 데스크톱 제어 권한을 부여하는 방향성은 아키텍처 측면에서 매우 효율적입니다. 

하지만 소형 모델(Gemma4-E4B)의 추론 한계와 로컬 PC의 보안 리스크를 고려할 때, 현재 계획에는 몇 가지 보완해야 할 취약점이 존재합니다. 이에 대한 개선안을 제안합니다.

## 1. 도구 혼재로 인한 환각(Hallucination) 방지
* **문제점**: `start_video_workflow`와 같은 '고수준 워크플로우 도구'와 `run_powershell`, `control_flow_desktop`과 같은 '저수준 OS 제어 도구'가 하나의 MCP에 모두 노출될 경우, 4B 파라미터 수준의 모델은 어떤 도구를 선택해야 할지 혼란을 겪고 잘못된 파라미터를 주입할 확률이 높습니다.
* **개선안**: 모델에게 노출되는 도구의 수를 최소화해야 합니다. OS 제어 권한을 주더라도, 비디오 제작과 관련된 데스크톱 제어는 `continue_video_workflow` 내부 백엔드 로직에서 자동으로 호출되도록 추상화(Abstraction)하는 것이 좋습니다. 즉, 모델은 "진행"만 명령하고, 클릭과 타이핑은 파이썬 백엔드가 알아서 처리하게 만들어야 모델의 인지 부하를 줄일 수 있습니다.

## 2. 하드코딩된 차단망(Interceptor) 도입 (시스템 파괴 방지)
* **문제점**: 샌드박싱이 제거된 상태에서 "지시문(System Prompt)에 위험한 행동을 하지 말라고 적어두는 것"만으로는 절대 안전하지 않습니다. 모델이 오작동하여 `Remove-Item`이나 `del` 같은 파괴적인 PowerShell 명령을 내릴 수 있습니다.
* **개선안**: `run_powershell` 백엔드 함수 내부에 강력한 **블랙리스트 정규식**(예: `rm`, `del`, `Remove-Item`, `Format-Volume`, `net user` 등)을 하드코딩해야 합니다. 해당 명령어가 감지되면 파이썬 단에서 실행을 즉시 차단하고, 모델에게 `"위험한 명령어입니다. 사용자에게 명시적인 텍스트 승인을 먼저 요청하세요."`라고 반환하는 인터셉터가 필수적입니다.

## 3. 상태 검증 없는 데스크톱 제어의 위험성
* **문제점**: `control_flow_desktop`은 화면의 픽셀 좌표나 특정 UI 요소를 찾아 클릭합니다. 만약 사용자가 Flow 창을 최소화해두었거나 다른 창이 가리고 있다면 엉뚱한 곳을 클릭하게 됩니다.
* **개선안**: 데스크톱 제어 도구를 실행하기 직전, 대상 브라우저(Edge/Chrome) 창이 최상단에 포커스(Focus)되어 있는지, 그리고 최대화(Maximized) 상태인지 검증하는 로직을 도구 내부에 반드시 추가해야 합니다. 상태가 올바르지 않으면 모델에게 "사용자에게 Flow 창을 띄워달라고 요청하세요"라고 반환해야 합니다.

## 4. `agent_mode_status` 도구의 통합
* **문제점**: 계획서에 새로 추가하기로 한 `agent_mode_status()`는 이전 계획에서 고도화한 `diagnose_runtime()`과 역할이 크게 겹칩니다. 도구가 늘어나면 모델의 혼란만 가중됩니다.
* **개선안**: 새로운 도구를 추가하지 말고, 기존 `diagnose_runtime()`의 반환값에 `powershell_access: unrestricted`, `desktop_control_ready: True` 등의 에이전트 권한 메타데이터를 덧붙이는 방식으로 통합해야 컨텍스트를 절약할 수 있습니다.

---

**결론적으로**, 샌드박스를 없애고 Agentic 기능을 부여하는 것은 강력하지만, 4B 모델의 특성을 고려하여 **"백엔드에서의 하드코딩된 안전장치"**와 **"도구 노출 최소화"**가 반드시 병행되어야만 워크플로우가 붕괴되지 않습니다. 

이 개선안을 반영하여 구현을 시작하는 것을 강력히 권장합니다.
